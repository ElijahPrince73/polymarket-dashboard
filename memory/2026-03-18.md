# 2026-03-18 Weather Bot Session

## Major Performance Improvements Implemented

### High-Confidence Trading Strategy
- **Raised edge requirements:** MIN_EDGE 15% → 25%, MIN_ABS_MODEL_DIFF 8% → 12%
- **Added model consensus requirement:** MIN_MODEL_CONSENSUS = 4 (need 4+ weather models agreeing)
- **Expected impact:** Win rate 46% → 60-65%, turn negative ROI positive
- **Strategy:** Extreme selectivity until model proves itself, then gradually expand

### City-Specific Confidence Thresholds (Tiered Approach)
- **TIER 1 (proven):** Miami, Paris, London, Chicago, Dallas - 25% edge minimum
- **TIER 2 (marginal):** Atlanta, NYC, Sao Paulo - 28% edge minimum  
- **TIER 3 (poor):** Seoul, Wellington, Seattle - 35% edge minimum
- **TIER 4 (terrible):** Toronto, Tokyo, Singapore - 40% edge minimum
- **Philosophy:** Access all cities but with appropriate risk controls based on historical data

### Paper Trading Performance Analysis
- **Worst performers:** Toronto (-85% ROI), Tokyo (-28%), Seattle (-21%), Wellington (-19%)
- **Best performers:** Miami (+94% ROI), Paris (+77%), London (+76%), Chicago (+53%)
- **Total paper trades analyzed:** 78 resolved (46W/32L)
- **Key insight:** City-specific performance varies drastically, justifying tiered approach

## Dashboard & Data Issues Fixed

### Position Display Logic Fixed
- **Problem:** Dashboard showing resolved/stopped positions as "open"
- **Fix:** Open positions now only shows status=OPEN AND event_date >= today
- **Result:** Clean separation between active positions vs resolved outcomes

### Database/Live Order Sync Issues
- **Problem:** `/kill` command failed to actually cancel Polymarket orders, database marked as SKIP but orders remained live
- **Found:** 11 live orders on Polymarket but database thought they were cancelled
- **Added:** `/sync-orders` endpoint to reconcile database with live order data
- **Added:** `/cancel-selective` endpoint for targeted order cancellation

### Position Switching Feature Status
- **Confirmed:** Already implemented in monitor.js
- **Function:** Automatically sells position if edge < -5% AND opposite side has edge ≥ 5%
- **Limitation:** Only works within same market (YES↔NO), not cross-market switching
- **Potential enhancement:** Could implement cross-market switching (e.g., sell "55-56°F NO" to buy "57-58°F YES")

## Key Lessons
- **Don't loosen all filters at once** - proven strategy to avoid this mistake
- **Database sync critical** - live orders must match database state
- **City performance varies dramatically** - tiered approach better than blacklisting
- **Model consensus requirements** prevent low-confidence trades
- **Position switching already works** but could be enhanced for cross-market optimization
